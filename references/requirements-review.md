# ניתוח דרישות — PRD, Figma ו-User Flows

מתי להשתמש: לפני שפיצ'ר נבנה (בדיקות "שמאלה" — לתפוס בעיות בנייר, הכי זול), כשהמשתמש
משתף מסמך אפיון/עיצוב, או כשבקשת בדיקה מנוסחת מולית מול "מה שהובטח".

## ניתוח PRD / מסמך אפיון — צ'קליסט

עברו סעיף-סעיף ושאלו:
- [ ] **בדיקוּת (Testability)** — האם לכל דרישה יש תוצאה שאפשר לקבוע עליה PASS/FAIL?
  "המסך ייטען מהר" לא בדיק; "המסך נטען תוך 2 שניות ברשת רגילה" בדיק.
- [ ] **שלמות** — מה קורה במקרה הריק (0 פריטים)? בשגיאה? בקלט לא חוקי? PRD שמתאר
  רק happy path הוא רשימת הבאגים העתידית.
- [ ] **סתירות** — סעיף 3 אומר X וסעיף 7 אומר ההפך? עדיפויות סותרות בין מסכים?
- [ ] **עמימות** — "בקרוב", "אמור", "בדרך כלל", "וכו'" — כל אחד מאלה = שאלה פתוחה.
- [ ] **תלויות** — הפיצ'ר מניח נתונים/הרשאות/מודול אחר שקיים? מה אם לא?
- [ ] **היקף שלילי** — מה הפיצ'ר *לא* עושה (out of scope) — כתוב או מנוחש?

פלט הניתוח: רשימת שאלות פתוחות למשתמש + טיוטת תרחישי בדיקה (ראה test-plans.md) —
כבר בשלב הזה, לפני שנכתב קוד.

## Figma / סקיצות עיצוב — צ'קליסט סקירה

- [ ] **מצבים חסרים** — לכל מסך: מצב ריק, מצב טעינה, מצב שגיאה, מצב עומס (100 פריטים,
  שם בן 40 תווים). פיגמה כמעט תמיד מציירת רק את המצב המאוכלס-יפה.
- [ ] **RTL ועברית** — כיווניות נכונה, טקסטים ארוכים בעברית לא נחתכים, מספרים/תאריכים
  מיושרים נכון בתוך RTL.
- [ ] **רספונסיביות** — יש עיצוב למובייל/טאבלט או רק דסקטופ? נקודות שבירה מוגדרות?
- [ ] **אזורי מגע** — כפתורים במובייל ≥44–48px; מרווח בין אלמנטים לחיצים.
- [ ] **עקביות** — אותם רכיבים (כפתור ראשי, שדה, כרטיס) נראים אותו דבר בכל המסכים?
- [ ] **נגישות** — ניגודיות טקסט/רקע, מצבי focus, טקסט שאיננו רק צבע.
- השוואת מימוש-מול-עיצוב (Pixel Perfection): פונטים, צבעים, מרווחים, היררכיה —
  כשיש קובץ עיצוב, הוא ה-expected result של בדיקת ה-UI.

## מיפוי User Flows

מפו כל זרימה מרכזית כרצף צעדים עם הסתעפויות — כל צומת החלטה הוא נקודת בדיקה:

```
[כניסה] → יש נתונים? ─לא→ מסך ברוכים הבאים → דמו/ריק/אשף  ← כל ענף = תרחיש
              │כן
              ▼
         דאשבורד → פעולה (הוספה/עריכה/מחיקה) → אישור? ─לא→ ביטול (מה קורה לנתונים?)
                                                  │כן
                                                  ▼
                                             שמירה → עדכון בכל התצוגות? (כלל 4b)
```

- כל חץ = מעבר שצריך בדיקה; כל "לא" = תרחיש שלילי שחייב תרחיש משלו.
- זרימות שנשברות באמצע (רענון, Back, סגירת טאב באמצע אשף) — על כל צומת.
- ספירת מסלולים: אם לזרימה יש יותר מ~7 מסלולים, בחרו לפי סיכון (הכי שכיח + הכי
  הרסני), ותעדו מה הוחלט לא לכסות.

פלט המיפוי: טבלת מסלול⟵תרחיש, שנכנסת לתור הדשבורד כ-checks עם module מתאים.
