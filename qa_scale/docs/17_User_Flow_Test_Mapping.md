# מיפוי User Flows ל-Test Cases

> מסמך זה מספק מתודולוגיה ודוגמאות מלאות למיפוי זרימות משתמש (User Flows) לתרחישי בדיקה (Test Cases).

---

## מתודולוגיה

עבור כל User Flow יש למפות:

1. **Happy Path** — הדרך המוצלחת, המשתמש מגיע למטרה ללא שגיאות
2. **Alternative Paths** — דרכים חלופיות שעדיין מגיעות למטרה
3. **Error Paths** — דרכים שבהן משהו משתבש והמערכת צריכה לטפל בשגיאה
4. **Edge Cases** — מקרי קצה, קלט לא שגרתי, מצבים נדירים

---

## דוגמה 3: זרימת חיפוש וסינון (Search & Filter)

### תיאור הזרימה
משתמש → מזין מונח חיפוש → צופה בתוצאות → מסנן תוצאות → מיין → בוחר מוצר

## טיפים למיפוי יעיל

1. **התחל מ-PRD** — כל User Flow שמופיע ב-PRD חייב לקבל מיפוי מלא
2. **סקירת Figma** — בדוק את כל המסכים והמצבים (States) בעיצוב
3. **תקשר עם מפתחים** — שאל על מקרי קצה שהם חוששים מהם
4. **העדף לפי סיכון** — זרימות בעלות השפעה גבוהה (תשלום, הרשמה) קודם
5. **עדכן מיפוי** — בכל שינוי PRD/Figma, עדכן את המיפוי
6. **סטטוס מעקב** — סמן כל תרחיש: 📝 לא נבדק | ✅ עבר | ❌ נכשל | 🔄 רגרסיה
